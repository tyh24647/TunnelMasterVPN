# Reference service setup

The service is source code, not a deployed backend. No paid infrastructure, OAuth applications, email messages, App Store products or accounts have been created on your behalf.

1. Create a Python virtual environment and install `Service/requirements.txt`. Export values from `.env.example` through your secret manager/process manager.
2. Run `uvicorn app:app --host 127.0.0.1 --port 8000` from `Service/`, behind an HTTPS reverse proxy. Keep the SQLite database and secrets outside public directories. Account/signup endpoints require abuse protection and proxy-aware rate limiting before public exposure.
3. Configure an HTTPS OIDC broker (e.g. your existing identity platform) with Apple, Microsoft, Discord, GitHub, Facebook and Google connections. Register callback `https://YOUR_API/v1/auth/callback`. Connection names in `.env.example` are examples, not universal provider IDs. Apple sign-in may require broker-specific first-login data handling and Apple account deletion/revocation support.
4. Configure SMTP. Run a single durable outbox worker calling `deliver_outbox()` periodically. Do not run multiple workers without database claiming/idempotency protection. Production should add retry backoff, bounces, retention, delivery telemetry, consent/abuse handling and bounce suppression. Crash-after-send can still duplicate mail with plain SMTP; use a mail provider's idempotency key for stronger delivery guarantees.
5. Configure Apple's app ID/bundle, trust roots from Apple PKI, and Sandbox or Production environment. Keep sandbox verification separate from production. The library verifies Apple's JWS chain before granting access; a client boolean never grants entitlement.
6. Supply a real gateway catalog. The sample remains offline. Operate gateways in your chosen countries or contract with a VPN infrastructure provider. No public third-party VPN is repackaged without authorization.
7. Implement the private provisioner at `PROVISIONER_URL`, protected by `PROVISIONER_TOKEN`, and enforce registered-device credentials, current entitlements, bandwidth tiers and multi-hop routes at gateway level.

## Provisioner contract

`POST /tunnels` receives:

```json
{"accountID":"UUID","deviceID":"UUID","entry":"us-ny-01","exit":null,"premium":false}
```

It must return a JSON `ProvisionedProfile` compatible with the app:

```json
{
  "profile": {
    "id":"8B7C68D8-69A1-4E65-82AA-63D13CB234E5",
    "name":"New York",
    "kind":"IKEv2 / IPsec",
    "server":"YOUR_REAL_GATEWAY",
    "remoteID":"YOUR_CERTIFICATE_ID",
    "localID":"",
    "username":"PER_DEVICE_USERNAME",
    "transport":"Automatic",
    "dnsUpstream":"1.1.1.1",
    "bypassDomains":[],
    "disconnectOnSleep":false
  },
  "password":"SHORT_LIVED_DEVICE_SECRET",
  "psk":null
}
```

Never return master gateway credentials. Native protocol paths are supported by this provisioning DTO. WireGuard hosted provisioning additionally needs a public-key registration flow so the client retains its private key; it is not implemented by the reference DTO. Own-server WireGuard import is separate.

## Purchases, family, referrals

Eight products are in `Configuration/TunnelMasterVPN.storekit`; create corresponding products in App Store Connect, configure seven-day introductory offers, and enable sharing only for family products. StoreKit's returned prices and Apple's payment sheet are authoritative. The client binds purchases to the service UUID with `appAccountToken`; the server verifies it for purchased ownership. Family recipients restore their Apple-issued shared entitlement; an invitation alone grants nothing.

A username-derived unique referral code is generated by the service (currently an automatically assigned `member-...` username). Referrals reject self-use, repeats, prior trial users and prior purchasers, and grant one calendar month of service credit. No Apple renewal date is silently changed. A separate seven-day lifetime service trial is non-billing and currently individual only; recurring family trials use Apple's introductory offer. Cross-system eligibility synchronization still needs hardening.

## Deliberate production gates

`COMMERCIAL_READY=false` is the default. Do not switch it on simply to make the purchase button work. Outstanding work includes:

- App Store Server Notifications V2, transaction status reconciliation, refund/revocation/upgrade/grace-period handling at server/gateway level. CurrentEntitlements protects the client UI but does not replace server notifications.
- Strong recipient-specific shared-transaction binding and account linking/recovery; replay prevention must cover shared transactions across service identities.
- Gateway credential revocation and complete account deletion. The current DELETE endpoint returns 503 until this is implemented; do not submit to App Review in that state.
- Anonymous hosted session/provisioning if accountless remote service is offered. Anonymous own-server profiles and DNS already work.
- Device removal/replacement and concurrency leases, short-lived VPN credentials, quota/rate enforcement, refunds, gateway abuse controls.
- Persisted purchase invitation intent for purchases that complete while the app is closed. Immediate verified purchases and later manual invitations are supported; deferred automatic invitations are not.
- Production privacy/retention policy, entitlement capacity limits, marketing claims based on measured performance, monitoring and disaster recovery.

## Testing StoreKit

The `TunnelMasterVPN-StoreKit` scheme loads the local catalog. Do not enable production purchasing or accept unverified JWS merely to test. Use Xcode's StoreKit Transaction Manager and a separate controlled test service that verifies the local StoreKit signing certificate, or Apple's Sandbox with the real verification path. The reference verifier deliberately trusts Apple certificate roots rather than arbitrary Xcode test transactions.
